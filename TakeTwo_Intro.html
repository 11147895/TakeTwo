一、产品定位

TakeTwo 是一个基于心理学体系的 AI 沟通训练平台——用户带来真实生活中"卡壳了"的社交场景，AI 用 25 种经过验证的心理学方法，一步一步引导用户完成训练。

核心理念：沟通不是"知道道理就能做到"。TakeTwo 不讲课，而是让用户在真实场景中反复练习，直到身体在那个时刻知道该怎么做。

它解决什么问题

每个人都遇到过——被当众质疑不知道怎么回、收到夸奖手足无措、想说"不"又怕伤关系。市面上有大量教沟通的内容（文章、课程、短视频），但"学过"和"做到"之间隔着一道鸿沟。TakeTwo 填补的就是这道鸿沟：把心理学方法变成可训练的交互体验，让用户不是在「听道理」，而是在「练肌肉」。

灵感来源

小红书上「领导说 XXX 怎么回」类内容动辄数万点赞——说明"卡壳"的普遍性。但这些帖子给的是模板，不是能力。TakeTwo 把"给模板"升级为"练能力"。

二、两种训练模式

⚡

「此刻」—— 急救模式

已经发生了，需要立刻知道怎么回应。
输入真实场景，AI 一步步引导你想出回应。

描述场景 → AI 匹配方法 → 分步引导 → 串联成完整回应
🏋️

「沙盘」—— 训练模式

还没发生，但知道自己容易在某种场景下卡壳。
在安全环境里反复练习，把方法变成肌肉记忆。

选关系 → 选卡壳点 → 5关渐进 → 复盘分析 → 推荐继续

关卡名称训练目标怎么练
第1关听懂识别对方话语的多重含义听到一句话，判断它可能的含义（多选题）
第2关看见自己觉察自己的本能反应模式同一句话，说出第一反应 → AI 判定反应模式（回避/防御/讨好/被动攻击/建设型）
第3关换一种方式用建设性方式回应AI 用心理学方法分步引导，每步评判纠偏
第4关稳住对方施压后依然保持建设性对方继续追问/施压，看你是否回到旧模式
第5关迁移在不同情境中运用同一能力换个说话者、换个场景，同样的能力还能用吗

场景变体系统

同一个场景类型（如"被当众质疑"）有 5 个难度递进的变体，从容易到难度逐步练习：

变体 1 · 直接质疑
"这方案你自己看过吗？"
变体 2 · 反问
"这方案你确定不用再看一遍？"
变体 3 · 讽刺
"看来你对这方案挺有信心的啊"
变体 4 · 借他人之口
"有同事反映这个方案有些问题"
变体 5 · 质疑能力
"这个水平的方案，不像你做出来的"

变体 1 走完整 5 关，变体 2-5 精简为 3 关（第2关→第3关→第4关）。预设不够时，AI 可实时生成新场景。

三、心理学方法库（25 种）

TakeTwo 的核心竞争力在于 有理论依据的 AI 引导。每种方法都来自经过验证的心理学或沟通研究体系，包含完整的步骤定义、评判标准和纠偏规则。

设计原则：方法在练习中自然引入，不是"先学后练"。用户不需要提前了解方法——练着练着，方法就长在身上了。

四、典型使用流程

「此刻」模式使用示例

👤 用户输入："刚刚开会，领导当着所有人说'这方案你自己看过吗？'"

🤖 AI 回应：我理解了——领导当众质疑了你的方案。我们用非暴力沟通的方法，一步一步来。这个方法的核心是：观察→感受→需要→请求。

第一步 · 观察：只说看到听到的事实。❌ "领导当众羞辱我"← 这是解读。✅ "领导在会议上问我有没有看过方案"← 这是观察。说说你的观察？

👤 用户回答……

🤖 评判：对了，你只说了事实。第二步·感受——你心里是什么感觉？

（继续引导感受→需要→请求，最后串联成一段完整回应）

「沙盘」模式使用示例

① 选关系：职场 → ② 选卡壳点：被当众质疑 → ③ 开始训练

第1关 · 听懂：领导在会上说"这方案你自己看过吗"。这句话可能的含义有哪些？（A.字面提问 B.对方案不满意 C.想当众羞辱你 D.希望你再检查）

👤 选了 A+B+D → ✅ 通过

第2关 · 看见自己：面对这句话，你的第一反应是什么？脱口而出那种。

👤 "我可能会解释方案已经反复检查过了"

🤖 判定：你的反应模式是防御型——本能想解释和自证。这个模式的代价是：对方会觉得你没有底气，下次还这样对你。

（继续第3关"换一种方式"→第4关"稳住"→第5关"迁移"）

五、关键设计特色

设计决策说明
教练式引导 AI 不讲道理、不甩模板。通过提问、倾听、纠偏让用户自己找到答案。纠偏时精准指出偏在哪里，但不直接给答案
评分有理论背书 每次评判都关联到具体的心理学方法和来源书籍，让用户知道"为什么这样算对"，不是主观打分
反应模式识别 沙盘第2关自动识别用户的本能反应模式——回避/防御/讨好/被动攻击/建设型。看到模式，是改变的第一步
好坏场景混合 不单独分"防御"和"接受"。被质疑要练，被夸也要练——被夸了只会说"没有没有"也是一种卡壳
方法自然引入 不是"今天学非暴力沟通第一章"。而是练着练着发现"这个方法好用"，然后才知道它叫非暴力沟通
不用角色卡 场景自带角色信息（说话者、关系、权力位置），AI 直接基于真实场景引导，不需要用户选角色/扮演
闯关感设计 沙盘模式用"第X关""过关""通关"等游戏化语言，降低训练的心理压力，增加完成动力
场景变体覆盖 同一种卡壳，对方从"直接说"到"借人之口说"练习维度不同，确保能力在真实生活中有覆盖度
可分享部署 Web 版部署在 GitHub Pages（静态前端），AI 调用走 Cloudflare Worker 代理（API Key 存在服务端环境变量，前端不暴露）；iOS 版走 WKWebView 原生壳直连。用户无需配置 Key 即可使用

七、复盘与成长追踪

每次训练完成后，AI 生成一份结构化复盘报告，包含以下维度：

维度内容
每步表现哪一步一次过、哪一步需要纠偏、哪一步卡住了，精确到每个步骤的状态（passed / needs_work / struggled）
反应模式分析初始反应模式 → 最终反应模式的变化轨迹，什么情况下容易回到旧模式
核心模式一句话描述用户的典型沟通模式，以及触发条件
优势与弱项至少 1 个优势 + 最多 2 个弱项（含改进建议），不让用户觉得"全是问题"
进步描述从第一次到最终回答的对比——让你看到实实在在的变化
下次推荐具体推荐下一次练什么、为什么、多久后重练（2/3/7天）
场景存档将你的回答存档到个人场景库，方便以后回顾

重练提醒机制：如果某步骤标注为 needs_work → 3天后提醒重练；若多个关卡为 struggled → 2天后重练；全部通过 → 7天后巩固。重练后全部通过则标记为"已掌握"。

八、实现方式

TakeTwo 采用 纯前端 HTML + JS 架构，关键特征：

🤖 AI Agent 模式

连接 AI API（兼容 OpenAI 格式），由 Agent 实时引导训练。适合追求最佳体验的深度练习。

工作方式：场景理解 → 方法匹配 → 分步引导 → 评判纠偏 → 复盘分析，全部由 LLM 驱动

📦 本地离线模式

6 种核心方法（非暴力沟通等）在本地完成完整训练判定，不需要联网和 API Key。

工作方式：基于 skills/ 目录中预设的步骤定义、评判规则和纠偏话术，纯前端完成全流程

技能体系

每种心理学方法定义在 skills/ 目录中（每方法一个文件），由 manifest.json 做路由、assembler.js 组装成方法库。每个方法是一个完整的知识结构对象，包含：

  • 步骤定义——每一步叫什么、目标是什么、正例反例
  • 评判标准——每步常见的错误类型和匹配的正则纠偏规则
  • 纠偏话术——每种错误对应什么样的引导提示
  • 场景匹配——哪些场景类型适合用这个方法来练
  • 元数据——version（版本）、notFor（负例：何时不该用本方法）、触发导向 description

部署方式：Web 版为纯静态前端部署在 GitHub Pages，AI 调用经 Cloudflare Worker 代理（Key 在服务端）；iOS 版走原生壳直连（Key 用户自填）。模型：deepseek-v4-flash。

1. 产品概述

产品名称：TakeTwo

命名来源：电影拍摄中导演喊 "Take Two"——重来一次，这次更好。也谐音"接招"（take two = 接住对方的话）。

一句话定位

基于心理学体系的沟通训练 App——不教话术，用心理学方法论练沟通能力。

灵感来源

沟通能力弱的人，能不能被称为弱势群体？生活中具象事件的折射、小红书"领导说XXX怎么回"类内容的系统化升级、以及对心理学的研究——市面上缺少将心理学理论转化为可刻意训练的能力工具。

核心差异

维度传统方案TakeTwo
交付物话术模板能力训练
方法来源经验总结/碎片帖25 种经典心理学方法（有理论背书）
使用方式搜索 → 背诵 → 套用输入场景 → AI 一步步引导练习 → 形成肌肉记忆
反馈无 / 社区点赞实时评判纠偏 + 反应模式识别 + 弱点分析
知识转化"知道做不到"低风险练习场 → 稳定迁移到真实生活

产品形态

AI 原生应用，用户与对话教练 Agent 通过聊天交互完成训练。不是一个"AI 版课程"，而是一个教练式练习工具。

2. 目标用户

用户 A 职场新人（0-3 年经验）

典型画像：23-26 岁，学生思维未切换
遇到的话内心典型错误回应
"这方案你自己看过吗？"慌了，觉得要被开沉默 / 过度道歉 / 委屈辩解
"你看着办吧"不知道边界在哪反复请示 / 自己瞎做 / 拖着不动
"这个不是你负责的吗？"不敢反驳默认背锅 / 当场翻脸 / 背后抱怨
"你这周就干了这些？"觉得自己不被看见列流水账 / 过度解释

核心问题：不会在权力不对等的对话中既保护自己又维护关系。

用户 B 职场中层（3-8 年经验）

典型画像：28-35 岁，上有领导下有团队，两头受气
遇到的话内心典型错误回应
"工资太低了，外面给得多"没权加薪，不能没人情感绑架 / 画饼 / 冷处理
"预算就这么多了"团队活干不完默默接受 / 跟团队抱怨领导
"这不是我们的事"项目推不动替对方干活 / 抄送大领导施压
"我直接跟小王说了"权威被架空跟下属发火 / 跟领导硬刚

核心问题：三线同时崩——维护权威 + 向上管理 + 处理人际。

用户 C 社交焦虑者

典型画像：任何年龄段，害怕社交场合，事后反复复盘
遇到的话内心典型错误回应
"你觉得呢？"大脑空白"嗯…我也没什么想法"
"你怎么还不找对象？"又来了，好烦尴尬笑 / 沉默 / 甩脸色
"最近手头紧，能不能…"不想借但不会拒绝借了后悔 / 拒绝后愧疚
"周末一起吃饭啊"不想去但怕伤感情答应后痛苦 / 临到取消

核心问题：把拒绝当攻击，把沉默当灾难，缺少安全感。

用户 D 亲密关系困难者

典型画像：在恋爱/婚姻中反复陷入同一类争吵
遇到的话内心典型错误回应
"你上次也是这样"又来了，永远翻不完"你能不能别翻旧账" / 也翻对方的
（不说话）不知道哪里又错了疯狂追问 / 也冷战 / 低姿态求和
"随便，你决定"怎么选都是错的真的随便选 / 追问到底 / 发火
"你根本不在乎我"我做了那么多你看不见列举做过的事 / 反击"你呢？"

核心问题：把情绪表达当攻击，缺少"翻译"对方情绪信号的能力。

用户 E 自我成长型

典型画像：主动学习者——读书、播客、课程消费者，但"知道做不到"
触发场景他们的状态核心痛点
读完了《非暴力沟通》知道四步法，开口还是老样子知识没变成肌肉记忆
上了沟通课课堂上练得很好，回到现实打回原形缺少持续练习的反馈环境
刷到小红书话术帖收藏了 100 条，真遇到还是懵碎片化知识无法迁移
做了 MBTI / 九型人格知道自己类型，不知道怎么改诊断有余，训练不足

核心问题：缺的不是"知道"，而是"练"——一个低风险的、有反馈的练习场。

3. 心理学方法库

25 种方法分为 7 大类，每种方法有明确的来源、核心逻辑和适用场景。在 Agent + Skill 架构中，每种方法对应一个独立的 Skill 模块。

3.1 自我觉察类 · 先看懂自己

方法来源核心逻辑适用场景
非暴力沟通
MVP		 马歇尔·卢森堡《非暴力沟通》 观察 → 感受 → 需要 → 请求 被激怒后不知道怎么表达；习惯性压抑或爆发
萨提亚沟通姿态 维吉尼亚·萨提亚 5 种压力姿态：讨好、指责、超理智、打岔、一致型 想知道"我为什么总是那样回应"
情绪焦点疗法 EFT 苏·约翰逊 情绪分初级/次级，次级是保护层 表面生气其实是害怕；在意却表现冷漠
ABC 认知模型 阿尔伯特·埃利斯 A 事件 → B 信念 → C 情绪，不是事件让你难受，是解读让你难受 "他一定是故意的"——区分事实和故事

3.2 冲突处理类 · 对方在攻击/施压

方法来源核心逻辑适用场景
关键对话 科里·帕特森等《关键对话》 先建安全感，再谈内容 跟领导谈加薪、跟伴侣谈底线——一开口就崩
高难度对话 道格拉斯·斯通《高难度对话》 事实层、情感层、身份层——哪层被触发就在哪层崩 "这不是钱的事"——其实是身份层被触发
CRIB 法则 《关键对话》 Commit → Recognize → Invent → Brainstorm 双方目标完全对立时找交集
降维回应法
MVP		 实践总结 不解释、不自证、不反击，给软钉子 被阴阳怪气时越解释越被动
事实锚定法 实践总结 用客观事实回应主观攻击，不进入情绪场 职场被甩锅、被质疑时用事实说话

3.3 边界与拒绝类 · 对方在越界

方法来源核心逻辑适用场景
课题分离
MVP		 阿德勒心理学《被讨厌的勇气》 分清"这是谁的课题"，不是你的不用接 被道德绑架、被催婚、被过度干涉
果断表达法
MVP		 实践总结 承认对方 → 表达立场 → 给替代方案 想拒绝但怕伤关系
D.E.S.C. 模型 莎伦·安东尼·鲍尔 Describe → Express → Specify → Consequence 需要明确说"不"并说明后果
灰岩法 Grey Rock 心理学实践 让自己变得无聊无反应，操控者失去兴趣 面对操控型/自恋型人格

3.4 亲密关系类 · 关系很重要，话不能说太绝

方法来源核心逻辑适用场景
戈特曼情绪急救 约翰·戈特曼《幸福的婚姻》 先修复情感连接，再讲道理 伴侣吵架翻旧账、冷战
爱的五种语言 盖瑞·查普曼 肯定言词、服务行动、礼物、精心时刻、身体接触 "我做了那么多他怎么看不到"
依恋理论 约翰·鲍尔比 安全型/焦虑型/回避型/恐惧型，不同沟通需求 "他一靠近我就想逃""她一冷我就慌"
情感账户 斯蒂芬·柯维 存款（积极互动）vs 取款（消极互动） "为什么一次没做好就把之前的全否了"

3.5 接受好意类 · 对方在靠近/示好

方法来源核心逻辑适用场景
接受力训练
MVP		 心理学实践 接受赞美/好意不是炫耀，是对给予者的尊重 被夸了只会说"没有没有"
自我同情理论 克里斯汀·内夫 对自己善意 → 人类共有体验 → 正念觉察 "我不配""我肯定不行的"
冒名顶替综合征应对 心理学研究 区分"我觉得我不配"和"事实是我配" 收到机会/升职时觉得"他们会发现我不行"

3.6 影响力与说服类 · 你需要让对方同意

方法来源核心逻辑适用场景
六大影响力原则 罗伯特·西奥迪尼《影响力》 互惠、承诺一致、社会认同、喜好、权威、稀缺 需要说服别人但不知道怎么开口
FBI 谈判术 克里斯·沃斯《绝不退让》 战术性共情 → 标注情绪 → 校准型问题 → 让对方觉得是自己的主意 对方很强硬，需要谈判
框架效应 丹尼尔·卡尼曼《思考快与慢》 同一件事换个说法，对方反应完全不同 提需求总被拒，可能是表达框架问题

3.7 自我修复类 · 自己说错了想补救

方法来源核心逻辑适用场景
三层修复法 《高难度对话》延伸 事实层道歉 → 情感层共情 → 身份层确认价值 说了伤人的话不知道怎么挽回
情绪急救法 实践总结 止血（暂停）→ 清创（命名情绪）→ 缝合（决定下一步） 被批评后情绪上头、当场没忍住

Skills 实现状态：全部 25 个 Method Skill 已按「每方法一文件」拆分在 skills/ 目录（manifest.json 提供路由元数据，assembler.js 组装为 METHOD_SKILLS）。每个方法包含：步骤定义、评判标准（含正则匹配纠偏规则）、正反例、场景匹配，并新增 version、notFor（负例）、触发导向 description。Agent Prompt 按需注入当前方法，不塞全部上下文。

当前可训练方法（已在 index.html METHOD_TRAINING 中配置本地步骤）：非暴力沟通、课题分离、果断表达法、降维回应法、接受力训练、事实锚定法（6 种，覆盖常见场景）。其余方法由 Agent 在 API 模式下动态加载。

4. 功能设计

4.1 此刻模式 · 急救

触发：用户刚遇到（或正在遇到）一个让 TA 不舒服的沟通场景，需要即刻帮助。

流程

用户输入："刚刚开会，领导当着所有人说'这方案你自己看过吗？'" ┌─────────────────────────────────────────┐ │ 对话教练 Agent │ │ │ │ Step 1：加载 scene-analyzer Skill │ │ → 结构化场景 + 匹配方法（非暴力沟通） │ │ │ │ Step 2：加载 method-nvc Skill │ │ → 按 4 步引导用户（观察→感受→需要→请求） │ │ → 每一步评判纠偏（最多 2 次） │ │ │ │ Step 3：加载 review Skill │ │ → 复盘报告 + 反应模式识别 + 存档 │ └─────────────────────────────────────────┘

交互示例

【Agent 开场】 我理解了你的情况。领导在会上当着同事的面质疑了你的方案。 我们用非暴力沟通的方法，一步一步来处理。核心是四步：观察→感受→需要→请求。 ──────── 第一步：观察 ──────── 📋 只说你看到、听到的事实，不加你的解读。 ❌ "领导当众羞辱我" ← 这是你的解读 ✅ "领导在会议上问我有没有看过方案" ← 这是观察 现在，试试只说出事实：他说的原话是什么？ 【用户】 领导在会上质疑我的方案 【Agent 纠偏】 接近了！但"质疑"还是带了一点你的判断。 更纯粹的观察是："领导在会上问我'这方案你自己看过吗？'" ——不评价他的动机，只复述事实。当你把"羞辱"换回"问了一句话"，情绪就已经开始降温了。 ──────── 第二步：感受 ──────── 你当时的感受是什么？注意感受是情绪词，不是想法。 ❌ "我觉得他不尊重我" ← 对动机的判断 ✅ "我感到很难堪" ← 真实的感受 【用户】 难堪，还有点生气 【Agent 纠偏】 ✅ 对了。"难堪"和"生气"都是真实的感受。很多人跳过感受直接进入反击或退缩——但当你承认"我难堪、我生气"，你才开始真正处理这件事。 ──────── 第三步：需要 ──────── 你的什么需要没有被满足？感受背后都有一个需要。 常见的：被尊重、被认可、被理解、安全感、自主权…… 【用户】 我想被尊重 【Agent 纠偏】 很好——被尊重是一个核心需要。还可以更深一层：你准备了很久的方案被一句话否定了，也许还需要你的努力被看见？ ──────── 第四步：请求 ──────── 你想提出什么请求？请求要具体、可执行，不是抱怨也不是命令。 ❌ "希望他别这样说话" ← 模糊 ✅ "希望他在有意见时能单独跟我说" ← 具体可行 【用户】 希望他下次有意见私下跟我说，别当着所有人 【Agent 总结】 🎯 把你说的四步串起来，就是一段完整的回应： "领导，上午在会上您问我方案的事，我当时有点难堪。我对这个方案花了不少心思，希望能了解您具体的意见。以后如果有建议，能不能单独跟我说？我更听得进去。" 这不是模板，是你自己想出来的。下次遇到类似场景，用你自己的话把这四层意思表达出来就行。

4.2 沙盘模式 · 训练

触发：用户选择一种关系类型和卡壳场景，提前进行系统性训练。

入口流程

选关系（职场 / 亲密关系 / 朋友 / 家人）→ 选卡壳场景（被当众质疑 / 被甩锅 / 被催婚 …）→ 开始训练

场景变体系统

同一场景类型，通过 5 种变体从易到难递进：

变体表达方式示例（被当众质疑）难度
变体 1直接质疑"你这方案你自己看过吗？"★★
变体 2反问"这方案你确定不用再看一遍？"★★★
变体 3讽刺"看来你对这方案挺有信心的啊"★★★
变体 4借他人之口"有同事反映这个方案有些问题"★★★★
变体 5质疑能力"这个水平的方案，不像你做出来的"★★★★★

五关训练流程（变体 1）

核心设计：沙盘统一使用 5 级关卡框架（听懂→看见自己→换方式→稳住→迁移），其中「换方式」关卡根据所选场景绑定的心理学方法，动态加载对应的训练步骤。每个方法在 METHOD_TRAINING 中定义了自己的子步骤（详见代码），但均映射到统一的 5 级框架中。

关数训练目标引导方式评判标准
第 1 关
听懂		 快速判断话语的多重含义 展示原话 → 多选含义选项（包含字面、隐藏、过度解读） 选中关键含义通过；漏掉提示；选过度解读纠偏
第 2 关
看见自己		 识别本能反应模式 "你的第一反应是什么？不用想，脱口而出那种。" 判定反应模式：回避型 / 防御型 / 讨好型 / 被动攻击型 / 建设型
第 3 关
换一种方式		 打破本能，找到建设性回应 按推荐方法步骤引导（4 步或 3 步），每步评判纠偏 做到建设型回应通过；回到旧模式纠偏
第 4 关
稳住		 对方不退让时持续稳住 对方继续施压："{follow_up_pressure}"，你没有退，怎么回？ 不崩溃也不攻击通过；退缩或反击纠偏
第 5 关
迁移		 换场景也能用同样能力 新场景新对象："{transfer_scene.speaker}说：'{transfer_scene.original_words}'" 直接用上方法优秀；需要提示合格；回到旧模式纠偏

变体 2-5 精简为 3 关：第 2 关（看见自己）→ 第 3 关（换一种方式）→ 第 4 关（稳住）。跳过"听懂"和"迁移"，因为同一场景类型下用户已建立认知。

反应模式参考

模式典型表现长期代价
回避型沉默、退缩、转移话题、快速退让对方觉得你好拿捏
防御型解释、反击、自证、推卸责任关系越来越僵
讨好型过度道歉、委曲求全、否定自己需要自己越来越累，对方不会更尊重你
被动攻击型表面顺从实则不满、阴阳怪气回击积怨爆发时伤害更大
建设型既表达自己又维护关系、有感受有需要有请求目标状态

5. 技术架构：Agent + Skill 混合

5.1 架构选型理由

核心原则：Agent 负责体验，Skill 负责内容。

对话教练的"温暖感"是 Agent 的职责——管理会话状态、语调、流程节奏。心理学方法的"知识结构"是 Skill 的职责——步骤定义、评判标准、正反例、纠偏话术。

维度纯 Agent 架构Agent + Skill 混合 (推荐)
Prompt 规模 25 个方法全在 System Prompt → 超过上下文窗口 文件全量加载（script 标签，几乎免费）；上下文只注入当前 1 个方法的完整内容 → Agent prompt 保持 2000 token 以内
加新方法 改 Agent 核心 prompt → 回归风险高 加一个 Skill 文件，Agent 无需改动
测试 改一处影响全局 每个 Skill 独立测试；Agent 和 Skill 解耦回归
Token 成本 每次对话把所有方法塞进上下文 按需加载，仅当前方法相关内容进入上下文
内容迭代 心理学顾问和工程耦合 Skill 文件由领域专家独立维护
延迟 3 个 Agent 串行，至少 3 次 LLM 调用 场景分析和复盘内化为 Skill，Latency 更低

5.2 对话教练 Agent（唯一入口）

角色：用户唯一直接交互的对话实体。负责会话管理、状态跟踪、语气语调、方法调度。

职责说明
会话状态管理当前模式（此刻/沙盘）、场景 ID、当前步骤/关数、用户已答内容、纠偏次数
Skill 调度根据场景引擎输出选择 Method Skill → 加载 → 按 Skill 步骤引导
评判与纠偏用 Method Skill 提供的评判标准检查用户回答 → 生成纠偏话术
语气风格口语化中文、不用"您"、纠偏不批评、肯定不夸张、每次输出 ≤150 字（引导）或 ≤200 字（纠偏）
模式切换根据输入判断是"此刻"急救还是"沙盘"训练，切换对应流程
复盘触发所有步骤/关卡完成后 → 调 review Skill → 将结果展示给用户

Agent System Prompt 结构（引擎端）

Agent 的 System Prompt 由 agent.js 中的 PromptBuilder 模块在每次 LLM 调用时动态拼装，包含以下层次：

// PromptBuilder.build() 每次调用时组装 1. _buildAgentCore() → Agent 人格骨架（始终不变，约 200 token） 2. _buildMethodLibrary() → 此刻模式阶段1注入全部方法摘要（供 LLM 选择） 或 _buildMethodInjection() → 阶段2+注入已选方法的完整 Skill 步骤 3. _buildNowModeInstructions() 或 _buildTrainingModeInstructions() → 模式流程 4. _buildOutputFormat() → 强制 STATE 标记输出格式 // 沙盘模式 5 级框架 变体1：听懂(level1) → 看见自己(level2) → 换方式(level3) → 稳住(level4) → 迁移(level5) 变体2-5：精简为 看见自己 → 换方式 → 稳住（3关） 映射函数：_sandboxStepToLevel / _sandboxLevelToStep // STATE 标记（Agent 输出，前端解析）

关键：Agent prompt 不包含任何具体方法的步骤、例子、纠偏规则。这些全部外置在 Method Skill 中，运行时按需注入。

5.3 Skill 层设计（当前实现）

核心目录：skills/ — 按「每方法一文件」拆分，由 manifest（路由）+ assembler.js（组装）组织。Agent 通过 getSkill() / getMethodNames() 等查询函数按需读取。纯前端内存运行，无需文件系统。

// public/skills/ 目录结构（本次拆分落地） skills/ ├── manifest.json → 25 条路由元数据（id / file / name / category / version / description / sceneMatches / notFor） ├── manifest.js → 同内容，同步加载载体（必须挂 window.SKILL_MANIFEST，供 assembler 读取） ├── nvc.js → 每方法一文件：完整步骤 + 正反例 + 纠偏正则 + version + notFor ├── satir.js → … │ ⋮ （共 25 个方法文件） ├── emotionalFirstAid.js └── assembler.js → 按 manifest 组装为 METHOD_SKILLS；暴露 getSkill / getSkillsForSceneType / getDefaultMethod / getMethodNames；保留 SCENE_ANALYZER / REVIEW / SCENE_GENERATOR （含历史方法名兼容别名，如 "情绪焦点疗法EFT" → "情绪焦点疗法"）

对应四段式 Skill 结构：① 元数据（manifest + version/notFor/description）→ 负责「被找到」；② 知识（steps/正反例/纠偏）→ 负责「教会它」；③ 可执行 Tooling 与 ④ 测试为规划项（见 5.5）。

7.1 关键设计决策

决策说明
不用角色卡场景自带角色信息，不额外引入角色扮演
好坏场景混合不单独分"防御"和"接受"，用户在真实生活中两种都会遇到
入口提问用"哪个最像你"不用抽象概念，用具体场景共鸣降低认知负荷
方法在练习中自然引入不是先学后练，而是练完才知道用了什么方法
